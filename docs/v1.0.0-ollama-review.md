# Ollama control contract research

Date: 2026-10-04; contract/fixture update 2026-10-05. P0-1 contract acceptance is complete for the narrow candidate below: pinned source inspection, twelve parser/wire/protocol fixtures and five expiry-policy fixtures. Unsupported operations remain disabled. The typed adapter, provider/persistence routing and explicit opt-in are integrated. Ollama remains off by default, experimental and not live-tested. This is a research target, not a tested compatibility range.

The inspected release tag is v0.35.1, commit `b0c1ca4f7549d7acdfa52a7dcffc934bc63a43ce`. Sources are pinned below. Moving API documentation supplies background, not versioned compatibility evidence.

## Required fixtures and later live checks

`src/ollama_contract.rs` now parses bounded resident/catalog/show evidence without a network client. The shapes follow pinned [API types](https://github.com/ollama/ollama/blob/b0c1ca4f7549d7acdfa52a7dcffc934bc63a43ce/api/types.go#L779): catalog exposes remote metadata, while resident inventory exposes context and expiry. The pinned [show handler](https://github.com/ollama/ollama/blob/b0c1ca4f7549d7acdfa52a7dcffc934bc63a43ce/server/routes.go#L1536) exposes remote fields for remote-backed models. The candidate classifier is a conservative GamePause policy, not an upstream compatibility guarantee.

Eight isolated tests cover malformed/error/oversized inventories, model-count caps, missing context/expiry, invalid/ambiguous identity and duplicate routes, changed tags/digests, remote aliases and unsupported capabilities, final-set eviction/context mismatch, and content reloading under another alias. Unknown or malformed expiry remains raw evidence; it never creates replay duration or indefinite residency. An unload acknowledgement supplies no inventory absence proof. Every model classification returns a replay block, including the local completion candidate. These checks preserve the original evidence and contain no mutation path.

`cargo test --locked ollama_contract -- --nocapture` passed, exit 0, eight tests. Bodies use fictional model names and synthetic digests, not real model data. The fixtures exercise parsing and comparison policy, not Ollama scheduling or active-inference behavior. No HTTP request, live probe, service change or model operation was performed.

The fixture target is the consumer contract, not an execution of upstream Ollama code. No fixture contacts a running provider. Source inference about scheduler deferral still needs future live evidence before claiming real non-interruption. Unsupported model formats, missing metadata, additional capabilities, embedding and unknown expiry refuse candidate capture. An unavailable candidate must never cause unload.

## Limited wire contract and acceptance

The pinned [runner](https://github.com/ollama/ollama/blob/b0c1ca4f7549d7acdfa52a7dcffc934bc63a43ce/llm/llama_server.go#L315) returns its per-slot `NumCtx`; parallelism is separately multiplied into the launch context. Candidate replay sends the observed per-slot value unchanged, bounded by the model's advertised context. It does not divide/multiply by guessed parallelism or claim original parallel/live-option restoration. Final identity/context/residency checks remain mandatory.

The pinned [source parser](https://github.com/ollama/ollama/blob/b0c1ca4f7549d7acdfa52a7dcffc934bc63a43ce/internal/modelref/modelref.go#L93) defines the `:local` suffix. Generate rejects a remote-backed alias with explicit local intent. Candidate requests use that suffix, refuse source-qualified/cloud/ambiguous input routes, and revalidate catalog identity before later dispatch. This prevents remote routing in the pinned implementation; it does not atomically bind a local name to a digest. A local catalog race still requires final identity verification and retained recovery on mismatch.

`ReplayCandidate` captures the narrow contract, then constructs empty unload/preload payloads without an HTTP dispatcher. It requires matching catalog identity, GGUF completion-only metadata, supported observed/model context and the selected expiry policy. Acknowledgement parsing refuses partial, inference, error or remote responses. The production watcher never calls it; runtime control awaits adapter and journal integration. Later adapters must journal first, recheck identity/games, bound transport/poll work, verify all promised final fields and preserve original obligations through failures.

Four added tests verify unchanged per-slot context and local request fields, unsupported capture/embedding/cloud/expiry refusal, strict acknowledgement validation, and an isolated HTTP sequence with continuing residency, eventual absence and alias reload. The mock uses a private ephemeral loopback listener, five bounded requests and no inference payload. `cargo test --locked ollama_contract -- --nocapture` passed, exit 0, twelve tests total. Expiry tests add five separate passing cases. This completes P0-1's source/fixture contract decision; it does not complete P1-1 or establish live compatibility.

## Prospective expiry policy

`ollama_expiry.rs` implements the selected absolute observed-deadline policy independently of the watcher. Capture requires a valid RFC3339 timestamp within the next 24 hours, or a valid already-expired timestamp. This 24-hour limit is a conservative GamePause experimental policy, not an Ollama API limit. Missing, malformed, zero/pre-epoch, indefinite/far-future evidence is refused. Numeric offsets and nanosecond fractions are supported; unknown `-00:00` offsets and leap seconds are refused. Native calendar validation uses the existing Windows dependency; expiry keeps nanosecond precision separately from Windows wall-clock precision.

Replay planning returns a positive finite duration or a distinct Expired result. It consumes time spent paused. A monotonic elapsed budget caps remaining residency within a process; a wall clock before capture refuses replay. After restart, only original absolute evidence remains available. A rollback that still leaves the clock after capture cannot be detected reliably across restart, so this policy does not claim exact elapsed-time preservation in that case. Once an expired obligation is resolved, later recovery integration must keep that resolution rather than resurrecting it after a clock change. A load taking longer than the available budget needs reconciliation before reporting restoration.

Later schema-3 recovery must persist policy/version, original capture/deadline evidence and resolved expiry outcomes. Changed settings must not reinterpret them. The expiry module creates no journal or mutation payload. Completion candidates now have prospective wire construction, but runtime control remains blocked until adapter and persistence integration. The policy preserves neither the original keep-alive setting nor conversations/KV cache.

Five isolated fixtures cover offsets/fractions/calendar validation, missing/invalid/indefinite evidence, absolute deadlines and expired outcomes, clock changes/restart planning, and exact capture-limit/subsecond boundaries. The first boundary test caught Windows SystemTime's 100-nanosecond quantization; deadline evidence now uses an exact duration since the Unix epoch. `cargo test --locked ollama_expiry -- --nocapture` passed after that correction, exit 0, five tests.

The pinned [scheduler](https://github.com/ollama/ollama/blob/b0c1ca4f7549d7acdfa52a7dcffc934bc63a43ce/server/sched.go#L1612) marks expiration and defers unloading while references remain active. Its completion path processes expiration later. The [embedding handler](https://github.com/ollama/ollama/blob/b0c1ca4f7549d7acdfa52a7dcffc934bc63a43ce/server/routes.go#L946) schedules before returning empty-input success. These observations inform the conservative contract; neither expiry nor mock HTTP tests establish actual vendor scheduling behavior.

Contributors should later record the exact executable version and candidate build, prove non-interruption during inference, compare promised identity/context/residency after recovery, and test expiry and external reload with private journals. No live Ollama evidence exists here.

Mixed direction-change fixtures now prove that a persisted completed provider remains complete across restart and that repause retires a completed disabled provider only after a successful journal write. Both provider roles are exercised in the coordinator fixture. The actual HTTP engine fixture disables restored LM, repauses only Ollama and retains Ollama's original candidate until final verification. These are isolated control/storage checks; native independent edit controls and explicit opt-in disclosure are implemented, with fixture-only acceptance.

## Experimental adapter implementation evidence

`ollama_session.rs` now consumes this pinned contract through a generic coordinator adapter and a bounded loopback HTTP transport. The typed journal loader and actual engine router are integrated; settings permit explicit experimental opt-in after native disclosure, with default enrollment off. No live vendor implementation was exercised.

The typed snapshot records original candidates/deadlines, the pinned source revision, expiry policy and progress. Unknown fields/contracts, duplicate routes, inconsistent deadlines and altered originals are refused. Unload/load acknowledgement stages remain distinct from final inventory proof. Catalog/show validation repeats before mutation; final verification compares the complete expected resident identity/context set. Game interruption preserves original candidates for repause rather than recapture. Metadata checks cannot atomically bind a mutable local tag to a digest; final verification and retained recovery still handle that race.

The transport accepts loopback endpoints and four API paths, uses ten-second requests and one-MiB response caps, and disables redirects/environment proxies. Empty local generate requests never start/stop services, download or supply inference input. Capture rereads residency and has a 256-model cap; sequential metadata requests may still take substantial time.

Thirteen adapter fixtures cover private HTTP lifecycle, redirect/oversize refusal, delayed unload, four pre/post-effect control failures with restart, final eviction/retry, unsupported and changed capture, changed catalog, between-load game interruption, guarded typed payloads, expiry, loads exceeding their remaining budget and capture-budget reset after earlier sessions. Over-budget content retains an expiry-pending obligation across restart and requires read-only absence; it sends no repeated load/unload to enforce expiry. The finite request budget does not promise exact vendor expiration timing or original keep-alive/parallel/live settings. Additional actual-engine HTTP fixtures cover shared on-disk intent before mutation, independent LM completion during disabled Ollama recovery, re-enablement, Ollama-only restart and competing endpoint ownership. The engine retains the adapter clock and claim across ticks. The native opt-in cancel/accept/stale-dispatch regression passes; physical comprehension and live-provider acceptance remain pending.

## Live evidence

Date: 2026-10-06. Ollama 0.35.1 on Windows 11, the pinned source revision, with one local GGUF model (27B, Q4_K_M, capabilities `tools`, `thinking`, `completion`, observed context 32768). GamePause ran as the debug `GamePauseCLI --headless` build with a private data directory, the LM Studio provider disabled and a renamed system executable registered as a custom game. Sections above this one describe the earlier source/fixture-only state and are kept as history.

Wire observations, made with direct loopback requests:

- `/api/ps`, `/api/tags`, `/api/show`, the `:local` route suffix and the `done_reason` `load`/`unload` acknowledgements match the parsed contract. `expires_at` carries a local numeric offset and seven fractional digits.
- The model's capability list made the original completion-only classifier refuse it, so capture unloaded nothing. The subset now accepts local GGUF models that advertise `completion` with other capabilities, except `embedding`.
- `keep_alive: -1` is reported as an expiry about 292 years ahead (year 2319). A nanosecond-string `keep_alive` with `num_ctx` reloads with the requested residency and the same observed context; 100 hours was accepted.
- An unload sent during a running generation is acknowledged at once. The model stays resident, with `expires_at` set to the unload time, until the generation ends; the generation completed with its full output. An unload for a model that is not loaded returns the same acknowledgement.

GamePause runs:

| Scenario | Result |
|---|---|
| Observation mode, game start/exit | Game detected; model, expiry and data directory journal untouched. |
| Default 5-minute keep-alive | Unloaded on game start, absence verified, reloaded after the restore delay with 294.5 s, the time remaining at capture, and context 32768; journal cleared. |
| Indefinite keep-alive | Reloaded as indefinite. |
| Game start during a generation | Pause deferred as waiting for inference, completed once the model left; generation output complete; restored afterwards. |
| Watcher killed mid-pause, new watcher after game exit | Journal reconciled and the model restored with 593 s of a 10-minute keep-alive. |
| Nothing loaded | Empty capture, pause and restore completed without control requests. |

Not exercised live: embedding or vision models, unload-only entries, several resident models and eviction, cloud/remote-backed models, catalog changes during a session, other Ollama versions, sleep/wake, the dashboard opt-in dialog, and a mixed LM Studio plus Ollama session. Those rely on fixtures. The expiry policy for new captures changed to `frozen-remaining-v1` on the owner's decision after these observations; the absolute policy described above remains for journals that already use it.

## LM Studio transport comparison

The [public load API](https://lmstudio.ai/docs/developer/rest/load) exposes context length, batch size, Flash Attention, expert count and KV offload, with an optional configuration echo. GamePause also captures arbitrary raw load fields, identifiers, variants, namespaces, TTL and original server state, and verifies those through its existing adapter. The documented public fields do not establish full replay parity. Keep the internal WebSocket path; replacing it requires field-by-field evidence and regressions.
