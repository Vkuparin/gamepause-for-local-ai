## Intended result

Add Hermes as a first-class provider beside LM Studio and Ollama. A recognized game or manual Pause AI releases the memory held by Hermes's managed local runtime. After the existing game guard and grace period, GamePause restores the runtime and the supported captured model state. Hermes remains open for its other features.

Support a Hermes-only setup with LM Studio disabled or uninstalled. Keep independent outcomes and recovery for every enabled provider. Adapt the native egui dashboard for three main providers, while retaining the separate Other AI apps provider. There are therefore four possible settings and recovery entries, one per kind.

The owner's later request authorized implementation and local candidate preparation. The package version is 2.6.0. User provider configuration and model residency were not changed. The owner withdrew the initial live-cycle authorization and asked to finish with mocks; no live model operation was performed.

## Research evidence and open questions

The [Hermes local-model guide](https://hermes-agent.nousresearch.com/docs/user-guide/local-models) describes a managed llama.cpp runtime, demand loading, a 15-minute idle unload, and support for independently operated servers. That last case requires an ownership distinction: using Hermes as a client does not make another server Hermes-owned.

The following source findings were checked at upstream commit [`e8c8e464715d11bfb7b3006edabff6b719a29b8b`](https://github.com/NousResearch/hermes-agent/commit/e8c8e464715d11bfb7b3006edabff6b719a29b8b). This is research evidence, not a compatibility claim for the user's installed build.

## Supported scope and behavior

Target Hermes Desktop on Windows x64 with its verified managed local runtime. Cloud providers, SSH/WSL/Linux runtimes, arbitrary OpenAI endpoints and externally managed llama.cpp servers are outside this adapter's initial scope. Route an external Ollama server through Ollama. Independently chosen executables remain under Other AI apps.

Use a conservative `SupportedFields` guarantee until evidence justifies something stronger. The minimum release contract is the verified managed runtime's original enabled/running state and exact captured resident model content, with the supported live context/preset fields identified by H260-1. Do not promise conversation/KV cache, active-request resumption, exact idle-time replay, or LM Studio's full raw-setting guarantee. Do not change Hermes's model selection, context override, reasoning preference, profiles or unrelated settings.

Hermes enrollment is explicit for v2.6.0: add a disabled `hermes-main` entry to fresh defaults and migrated settings. Enabling it clearly explains that GamePause temporarily turns off the managed local runtime and restores the recorded state. Preserve existing LM Studio and Ollama choices; replacing LM Studio is the user's choice. Unit-test defaults also keep Hermes off.

| Capture condition | Required behavior |
|---|---|
| Hermes absent or closed, with no obligation | Quiet Not running; no app launch, install or configuration write. |
| Runtime already off | Leave it off; no restore obligation created for turning it on. |
| Runtime running but no resident models | Capture the runtime obligation if a gaming hold is needed. Restore an empty running runtime without loading the selected default. |
| Verified residents, all idle | Persist capture, then stop the managed runtime through Hermes and verify its effects. |
| Loading, generating, queued work, or unknown busy evidence | Defer active pause under the existing busy policy. No force-kill fallback. |
| Stale records, wrong owner, auth failure, malformed inventory or unsupported build | Refuse active control with a provider-qualified reason; preserve any pending recovery. |
| A provider becomes unavailable after a successful capture | Retain recovery and allow other providers to complete independently. |

Distinguish absence from an inaccessible existing installation. A refused connection on an initial probe is not sufficient to discard evidence of a live owner or a pending obligation.

## Capture, pause and restoration

Capture identifies the installation/runtime scope, profile/configuration authority, control owner, managed router and all resident models. Model identities use exact variant IDs plus verified local content identity. Record required split weights, vision projectors and draft models when present. A catalog label, model ID or path alone is insufficient to authorize restoring changed content. Bound identity work and cache it by file identity; avoid hashing multi-gigabyte weights on each watcher tick.

The Hermes-owned snapshot version 1 records immutable original evidence separately from mutable operation stages. It includes the original enabled/running state, actual supported model fields, content identities, both route identities and any sealed information needed after restart. Keep credentials in memory or reacquire them from verified private files. If durable secret evidence is essential, seal it with per-user DPAPI; never emit it through Debug, errors, logs, status or diagnostics. Do not serialize whole Hermes configuration files.

Each mutation has its own coordinator checkpoint and fresh guard:

1. Read and validate capture and busy evidence. Claim the managed runtime scope and both routes without waiting.
2. Persist the complete original capture and stop intent atomically before the lifecycle request.
3. Revalidate the owner, original state and busy evidence immediately before stop. Stop through Hermes's native API. Do not kill its desktop or a generic `llama-server.exe`.
4. Verify runtime disabled state and absence of the exact managed router/model children. A 200 response or an unreachable endpoint alone does not prove memory was released. Persist verified pause completion.
5. On restore, reconcile durable stages with fresh evidence, including a lost stop response or GamePause restart while Hermes is disabled.
6. If required, checkpoint and start the runtime through Hermes. Verify the new process/endpoint against the same captured installation. Keep original binding and snapshot bytes immutable; represent a verified port change as adapter-owned reconciliation evidence.
7. Checkpoint each load of an originally resident model. Revalidate content and supported settings. Use `/models/load`, never activate/select a default or send inference.
8. Verify all promised model fields and original runtime state, persist completion and clear only after the whole session is verified.

H260-1 must define the uncommon `enabled = false` but running case. Do not force enabled to true and call that a faithful restore. Refuse unsupported state combinations before mutation.

Native stop is a durable off setting, not a scoped lease. Journal recovery must survive app crashes, failed writes, stop/start timeouts, token rotation and dashboard shutdown. If Hermes is closed after pause, report how to reopen it and retry; v2.6.0 does not silently launch the desktop or reconstruct its private command. Conflicting user/profile/model/runtime changes require manual resolution without overwriting them. When a deliberate user turn-off cannot be distinguished from GamePause's recorded stop, H260-1 must specify the conflict policy and disclosure; it cannot claim the API proves who made that edit.

A verified completed pause stays quiet. GamePause does not repeatedly stop a runtime that the user explicitly re-enables. A future game or recovery step rechecks identities. Document that external actions can override the hold. A new game during restoration interrupts between units and repauses through the same durable original capture. Power changes invalidate transient verification and start the existing post-resume guard/grace policy.

## Integration and persistence

- Add `Kind::Hermes`, `config::Provider::Hermes` and `recovery::Payload::Hermes`. Keep the adapter in a Rust root facade with private children and `<module>/tests.rs`; do not put Hermes payloads in LM or Ollama types.
- Extend `provider_runtime::Providers` with typed Hermes dispatch beside Process, retaining the existing tested LM/Ollama router. Preserve exact queued-work binding checks, independent retries, continuation and completed-provider behavior.
- Retain the runtime/claims on the control thread. Discovery reads bounded local metadata on the discovery worker; detection publishes cached process evidence. Neither thread calls model operations. UI status uses cloned shared evidence without HTTP polling.
- Claim the installation's shared managed runtime as well as both normalized endpoints. Detect overlapping control through Other AI apps and refuse duplicate ownership before stopping anything. Account for shared runtime ownership across Hermes profiles and GamePause data directories.
- Plan settings version 5 with a guarded version-4 migration and byte-identical `config.v4.backup.json`, preserving existing version-2/version-3 migrations and their backups. Add Hermes disabled, preserve explicit omissions/choices, and refuse ID collisions rather than overwrite an entry. Explicit opt-out must survive future loads.
- Keep recovery envelope version 3 if its existing shared fields suffice; add versioned Hermes payload validation and raise the supported set to four. If H260-1 proves a shared format change is needed, revise this specification and design its guarded migration before implementation. Do not reinterpret old payloads.
- Pending Hermes recovery blocks changes to its unresolved ID, installation/profile, routes and lifecycle settings. Other completed providers and presentation preferences remain independently editable under current rules.
- Observation and Doctor perform no migration, model operation, automatic startup, preset reload or Hermes configuration write. No runtime/model downloads, telemetry, secret uploads or recursive install scanning are added.

## Dashboard and diagnostics

Preserve Rust eframe/egui with Glow and AccessKit. Display main providers in stable order: LM Studio, Ollama, Hermes. Show Other AI apps separately when configured. Disabled/uninstalled providers stay hidden under the existing visibility policy, while unresolved recovery always remains visible and named.

Replace the hero's fixed 112-point text-height assumption with measured content height. At normal widths, reserve room for the primary action beside the content; at compact widths, place it below. Allow three main-provider rows plus an Other AI apps row, game name, memory estimate and hint without overlap. Provider names remain readable; longer outcomes wrap or expose their complete accessible detail. Do not shrink type to make four rows fit.

Give Hermes a dedicated Advanced settings page and diagnostics section. Keep the existing provider tabs usable with the additional page at compact widths, using wrapping or a scrollable selector. Preserve draft rebasing, save/error feedback, dirty-discard behavior and per-provider recovery edit guards. Basic provider status and failure reasons require no Advanced toggle. The tray retains its fixed quick controls.

Differentiate local runtime paused, waiting for idle, restoring, not running, unavailable control and unresolved recovery. Idle Ready describes the last known app state, not continuously polled model residency. Whole-session success cannot mask a Hermes failure. Only add Hermes memory to the approximate freed-memory figure when capture has comparable verified byte evidence; otherwise omit its contribution.

Include Hermes in provider-scoped round-trip verification and availability, including Hermes-only settings. Verify lifecycle and promised fields through the same journal and units used during gaming. Redact credentials and private startup details from all diagnostics. Preserve existing CLI line fields and add Hermes to typed provider outcomes.
